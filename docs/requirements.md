# 毎日のごはんレシピ提案システム 要件定義（ドラフト v2）

## 1. 概要

NotebookLM で調べたレシピを Obsidian に貯め、条件に合うレシピを提案する個人用 Web ページ。
あすけんに記録しやすいよう、料理名と栄養情報もあわせて表示する。

```
NotebookLM（YouTube・Web をソースに調査）
   │ 決まった形式で出力 → コピー
   ▼
Obsidian（vault/レシピ/ に 1 レシピ 1 ノートで保存）
   │ Obsidian Git で GitHub に push
   ▼
GitHub Actions（ノートを読み取ってレシピ一覧 JSON を作る）
   │
   ▼
GitHub Pages の Web ページ（提案・検索・あすけん用コピー）
```

## 2. 決定事項

| 項目 | 内容 |
| --- | --- |
| 利用者 | 自分ひとり（個人用） |
| 調査 | NotebookLM。YouTube や Web のレシピをソースとして追加し、`vault/NotebookLMプロンプト.md` のプロンプトで出力させる |
| 蓄積 | Obsidian。このリポジトリの `vault/` フォルダを Vault として開き、Obsidian Git で同期する |
| 取り込み頻度 | 毎日少しずつ（1 日 1〜5 件程度） |
| 提案・検索 | GitHub Pages の Web ページ。スマホのブラウザから使う |
| 料理名・栄養値 | NotebookLM に出してもらう。ソースに記載がない場合は推定値とし、`栄養値: 推定` と記録する |
| 対象の食事 | 朝・昼・夕を画面で選べる |
| AI の API | 使わない（NotebookLM は手作業で使う） |

## 3. レシピノートの形式

1 レシピ 1 ノート。ノートの先頭のプロパティ（YAML）に情報を書く。

| プロパティ | 型 | 内容 |
| --- | --- | --- |
| 料理名 | 文字列 | あすけんで見つかりやすい一般名 |
| 元タイトル | 文字列 | ソースでのタイトル |
| 出典 | URL | 元の動画・記事 |
| 出典種別 | 文字列 | YouTube / Web |
| 食事 | リスト | 朝・昼・夕 |
| ジャンル | 文字列 | 和食・洋食・中華・韓国・エスニック・その他 |
| 調理時間 | 数値 | 分 |
| 人数 | 数値 | レシピが何人分か |
| カロリー〜塩分 | 数値 | 1 人分の kcal・g |
| 栄養値 | 文字列 | 記載あり / 推定 |
| 材料 | リスト | `材料名 グラム数g（元の分量）`。グラム数はレシピ全体の量 |

サンプル：`vault/レシピ/` の 3 件。

## 4. 機能要件（Web ページ）

### 4.1 提案・検索
- 食事（朝・昼・夕）を選んで提案を表示する
- 絞り込み：調理時間（例：15 分以内）、ジャンル
- 食材で検索：入力した食材を使うレシピを、一致数の多い順に並べる
- 「別の案」ボタンで提案を引き直せる

### 4.2 あすけん入力の補助
- 料理名と、1 人分のカロリー・たんぱく質・脂質・炭水化物・塩分を表示する
- 食材ごとの分量（g）の一覧を表示する
- 推定値の場合はその旨を表示する
- それぞれワンタップでコピーできる

### 4.3 その他
- 人数の切り替え：材料のグラム数を人数に合わせて換算する（栄養値は 1 人分のまま）
- お気に入り登録：ブラウザ（localStorage）に保存する
- 元の動画・記事へのリンクを表示する

## 5. 非機能要件
- 既存のタイマー（`index.html`）と同じく、ライトとダークの両方の表示に対応する
- スマホ幅で崩れない
- 費用は無料の範囲（GitHub Actions・GitHub Pages）

## 6. 制約と注意点
- NotebookLM（個人向け）には API がないため、出力のコピーと Obsidian への保存は手作業になる
- 栄養値はソースに記載がなければ NotebookLM の推定値になる
- 無料プランの GitHub Pages はリポジトリが公開のときだけ使える。そのため、手順の本文は保存せず、材料と出典リンクだけにする
- Obsidian Git はスマホ版（特に iPhone）では動作が不安定なことがある。レシピの追加は PC で行う想定
