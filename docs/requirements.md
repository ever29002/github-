# 毎日のごはんレシピ提案システム 要件定義（ドラフト）

## 1. 概要

YouTube と Web のレシピを毎日自動で集めて蓄積し、条件に合うレシピを提案する個人用 Web ページ。
あすけんに記録しやすいよう、料理名と栄養情報もあわせて表示する。

## 2. 決定事項

| 項目 | 内容 |
| --- | --- |
| 利用者 | 自分ひとり（個人用） |
| 形態 | 静的 Web ページ（HTML/CSS/JS）。GitHub Pages で公開し、スマホから使う |
| 収集元 | YouTube（YouTube Data API）と Web のレシピサイト。X は対象外 |
| 収集タイミング | GitHub Actions で毎朝自動実行し、結果を JSON でリポジトリにコミットする |
| AI（LLM API） | 使わない。整形と栄養計算はルールと辞書で行う |
| 対象の食事 | 朝・昼・夕を画面で選べる |

## 3. 機能要件

### 3.1 レシピ収集（GitHub Actions）
- 毎日 1 回、YouTube と登録済み Web サイトから新着レシピを取得する
- 取得する項目：タイトル、元 URL、サムネイル、材料と分量、調理時間、何人分か
  - Web サイトは、ページに埋め込まれた構造化データ（schema.org の Recipe）から読み取る
  - YouTube は、概要欄に書かれた「豚こま 200g」のような材料行を読み取る。材料が取れない動画は保存しない
- 同じ URL は重複登録しない
- 著作権に配慮し、手順の本文は保存しない。材料・分量と元ページへのリンクだけを保存する

### 3.2 提案・検索
- 食事（朝・昼・夕）を選んで提案を表示する
- 絞り込み条件：調理時間（例：15 分以内）、ジャンル（和・洋・中・その他）
- 食材で検索：入力した食材を使うレシピを、一致数の多い順に並べる
- 「別の案」ボタンで提案を引き直せる

### 3.3 あすけん連携（手入力の補助）
- 料理名を、あすけんで見つかりやすい一般的な名前に変換して表示する
  - 例：「やみつき！ご飯がすすむ豚こま生姜焼き」→「豚の生姜焼き」
  - キーワード辞書で変換する（辞書は手で追加・修正できる）
- 1 人分のカロリー、たんぱく質、脂質、炭水化物、塩分を表示する
  - 材料と分量を、食品成分表をもとにした栄養辞書で合計して求める
  - 辞書にない材料は計算から除き、その旨を表示する
- 食材ごとの分量（g）の一覧も表示する
- それぞれワンタップでコピーできる

### 3.4 その他
- 人数の切り替え：分量を人数に合わせて換算する
- お気に入り登録：ブラウザ（localStorage）に保存する

## 4. 非機能要件
- 既存のタイマー（`index.html`）と同じく、ライトとダークの両方の表示に対応する
- スマホ幅で崩れない
- 費用：無料の範囲で運用する（YouTube Data API の無料枠と GitHub Actions の無料枠）

## 5. 制約と注意点
- AI を使わないため、栄養値は概算になる。調味料の「少々」「適量」などは計算に含めない
- 料理名の変換精度は辞書の充実度しだい。最初は代表的な料理 100 件程度から始める
- YouTube Data API の利用には Google Cloud の API キー（無料）が必要。リポジトリの Secrets に登録する
- Web サイトは、利用規約と robots.txt で取得が認められているサイトだけを対象にする
